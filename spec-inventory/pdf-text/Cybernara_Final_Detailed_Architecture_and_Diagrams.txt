1. Architecture Overview
The reference architecture uses a modular transactional core, independently scalable worker pools, and replaceable infrastructure adapters. PostgreSQL is authoritative; object storage holds
evidence; search/vector/cache are rebuildable. Framework content and mappings are immutable by version. Assessments pin content and question versions, and reports render from frozen
snapshots.
Architecture concern
Decision
Deployment boundary
Single-customer private cloud, with optional internal workspaces/tenants and a future managed deployment path.
Transactional boundary
Modular monolith for high-integrity workflows; outbox events coordinate asynchronous work.
Service extraction
Extract reporting, connectors, AI or high-volume monitoring when independent scaling/isolation outweighs
distributed-system cost.
AI boundary
All model access through policy gateway; no UI/provider coupling and no autonomous authoritative decisions.
Data boundary
Tenant-aware PostgreSQL/object prefixes; framework content versioned separately from tenant execution.
Security boundary
Untrusted clients, connectors and models terminate at enforcing gateways; workload identity and default-deny internal
policy.

12. Data Architecture
Store
Authoritative data and design
PostgreSQL
Identity, content registry, mappings, assessment, privacy, risk, workflow, connector state, AI provenance, reports and audit
metadata. Multi-zone HA, PITR, encryption and partitioning.
Object vault
Evidence, source packages, generated reports, evaluation artifacts and signed manifests. Versioning, KMS, retention lock,
quarantine and lifecycle tiers.
Search/vector
Requirement/control search, approved knowledge chunks and analytics indexes. Documents include tenant ACL, source
ID/version/checksum. Fully rebuildable.
Redis/event infrastructure
Short-lived cache, locks, rate limits and job coordination. No irreplaceable business state.
Audit archive
Append-only integrity-chained event partitions and periodic signed verification manifests in WORM-capable storage.
Analytics read models
Materialized/projected metrics for dashboards and warehouse delivery; metric definitions versioned and lineage-preserving.
13. Consistency and Failure Model
Flow
Consistency and recovery
Framework publish
Validate in staging, sign pack, publish registry and emit change event atomically; rollback activates prior pack.
Assessment creation
One transaction pins scope, content/mapping/question versions and creates control instances.
Evidence upload
Pending metadata -> quarantined object -> scan/hash -> committed; reconciler repairs orphaned states.
Connector sync
At-least-once collection with external ID/version idempotency and periodic reconciliation.
AI generation
Generation is non-authoritative; failures return curated approved baseline; provenance persists before publication.
Report export
Worker renders frozen snapshot; retries are idempotent by snapshot/template/format key; completed artifact is immutable.
Audit
Business transaction writes outbox/audit intent; integrity writer chains and archives with monitored delivery.

14. Scalability and Availability
Component
Scale strategy
Web/API
Stateless replicas, connection pooling, request quotas, cursor pagination and read-model caching.
Assessment workers
Partition queues by tenant/work type; autoscale by age/depth; protect database with concurrency budgets.
Connectors
Per-connector/tenant rate limits, sharded schedules, incremental cursors and isolated failure pools.
Reporting/imports
Dedicated resource pools, streaming I/O, checkpoints and temporary object storage.
PostgreSQL
HA primary, read replicas, partition audit/large execution tables, online indexes and archival.
Search/vector
Shard by deployment/tenant scale, alias-based reindexing and source-checksum reconciliation.
AI
Per-tenant budgets, concurrency limits, batching where safe, model circuit breakers and private endpoint pools.
15. Architecture Decision Records
ADR
Decision
ADR-001
Start with modular monolith plus workers; preserve ports/events for extraction.
ADR-002
PostgreSQL is the system of record; JSONB only for typed extensibility, not core relationships.
ADR-003
Frameworks and mappings are signed immutable content packs.
ADR-004
Assessment and report reproducibility requires pinned snapshots and version IDs.
ADR-005
AI is advisory and provider-neutral with human publication/decision gates.
ADR-006
Private-cloud and customer-controlled encryption are first-class deployment requirements.
ADR-007
Search, vector, cache and analytics are derived and cannot grant authorization.
ADR-008
Transactional outbox is mandatory for committed state followed by asynchronous effects.
16. Operational Readiness

Runbooks cover database failover, queue backlog, connector compromise, evidence malware event, AI provider incident, key rotation, restore and integrity verification.

Dashboards expose SLOs, dependency health, job age, connector freshness, evidence scan backlog, audit delivery and AI quality/cost.

Quarterly restore and incident exercises; annual independent penetration testing and after material architecture change.

Capacity, threat model, privacy impact and model risk reviews are required before major release.
